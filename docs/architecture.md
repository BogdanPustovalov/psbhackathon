# Архитектурные решения

## Векторное хранилище

Для хранения эмбеддингов используется Chroma в persistent-режиме. База
работает внутри backend-процесса, а каталог `data/chroma` монтируется в Docker
как данные приложения. API обращается к хранилищу через интерфейс
`VectorStore`, поэтому детали Chroma изолированы в `ChromaVectorStore`.

## Поток запроса

1. API принимает вопрос пользователя.
2. Embedding provider превращает вопрос в вектор.
3. Vector store возвращает top-k фрагментов.
4. Reranker уточняет порядок релевантности.
5. LLM получает вопрос и ограниченный контекст.
6. API возвращает ответ и источники.

## Поток индексации

1. Пользователь загружает документ.
2. Ingestion worker извлекает текст.
3. Text splitter делит текст на чанки с overlap.
4. Embedding provider строит векторы.
5. Vector store сохраняет векторы и metadata.

## Наблюдаемость

Рекомендуемые метрики: latency каждого этапа, token usage, Recall@K, MRR, доля ответов без источников и ошибки провайдеров.
